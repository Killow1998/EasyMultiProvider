# EasyMultiProvider v0.7.5 Specification

Status: implemented; real cross-provider acceptance pending

## Objective

Make an already-compacted Codex task usable on an external model without
changing Codex-owned threads, resume data, SQLite projections, or rollout
files. The first request must either receive a complete visible context or fail
once at the correct HTTP/WebSocket error boundary.

Codex remains the only owner of history. EMP owns only request-local reading,
normalization, protocol projection, and context-budget enforcement.

## Clean boundaries

EMP must not:

- persist a second conversation/history database;
- modify `state_*.sqlite` or rollout JSONL;
- decrypt or forward source-bound opaque reasoning;
- log prompts, summaries, tool payloads, responses, credentials, or rollout
  content;
- treat a failed or interrupted destination turn as successful history;
- silently truncate or heuristically summarize visible history;
- retry an unchanged reconstruction or context-length failure.

## Route behavior

There are two relevant route classes:

- **Native:** the current Codex login and imported ChatGPT subscriptions. They
  share Codex/OpenAI's native compaction semantics.
- **External:** API Providers and gateways managed by EMP.

The routing decision is deliberately small:

1. Full visible input is forwarded through the normal protocol projection.
2. EMP `emp1:` compaction is already portable and follows the normal path.
3. Native opaque compaction sent to a native destination remains untouched.
4. Native opaque compaction sent to an external destination invokes the
   read-only history projection.

No process-local route cache participates in this decision. A failed first
request therefore cannot change the behavior of a retry.

## Codex history adapters

Routing knows one interface:

```text
read_visible_history(anchor) -> HistorySnapshot
```

Version-specific details remain behind:

- `AppServerReader`: accepts `thread/read(includeTurns=true)` from an injected,
  already-reachable App Server transport;
- `SQLiteReader`: opens the Codex state database read-only and locates the
  rollout path and history mode;
- `RolloutReader`: parses a captured complete JSONL prefix without writing it.

The default local path is SQLite locator plus rollout reader. App Server access
is optional until EMP has a stable, non-owning transport to an already-running
server; EMP never starts a second App Server for history reads.

## Successful-history boundary

The request anchor uses `thread-id` (or `session-id`) and the turn ID from
`x-codex-turn-metadata`. For Responses WebSocket requests, the canonical turn
metadata is the JSON string in
`client_metadata["x-codex-turn-metadata"]`; upgrade-handshake metadata is only
a fallback for non-WebSocket requests. Malformed canonical metadata fails
closed instead of falling back to stale connection metadata.

The rollout snapshot ends before the first record belonging to the incoming
turn. When an ephemeral incoming turn has not reached the rollout yet, EMP may
use the complete captured prefix only if every explicit turn in that prefix has
a successful `task_complete`; an unterminated turn fails closed. A prior turn
is history only when its terminal `task_complete` record has no error. Failed
and interrupted attempts, including their `TurnContext`, user input, and tool
events, are excluded.

For App Server data, only turns with `status == "completed"` before the incoming
turn are eligible. `failed`, `interrupted`, and `inProgress` turns are excluded.

## Visible projection

EMP normalizes only content Codex already exposes:

- user and assistant messages;
- tool calls and matching results;
- command/file activity that Codex exposes as visible items;
- visible plans, constraints, decisions, progress, errors, and blockers;
- supported image references;
- a plaintext compaction summary when Codex actually provides one.

Hidden reasoning and chain-of-thought are discarded. Tool call/result pairs are
atomic; an incomplete pair fails closed.

The destination input is built in one of two lossless forms:

```text
visible Codex compaction summary + completed tail + current request
```

or, when OpenAI remote compaction exposes only encrypted content:

```text
complete local visible history + completed tail + current request
```

EMP inserts one content-free handoff boundary immediately before the exact
current request. It tells the destination that earlier requests and acceptance
phrases are historical; it does not summarize, rewrite, or persist user
content. The current request remains the final input item.

EMP does not pretend the encrypted remote summary is readable and does not
replace it with a clipped home-grown summary. If the lossless projection does
not fit the external model's safe context budget, EMP returns
`context_budget_exceeded` before contacting the Provider.

At a Responses WebSocket connection boundary, EMP treats native and external
destinations differently. For a native Codex subscription, an unavailable
`previous_response_id` returns the standard `previous_response_not_found`
error so Codex performs its own full-request retry; EMP does not reconstruct
native history. For an external destination, EMP removes the unusable
predecessor and marks the exact current input for request-local reconstruction
from Codex's read-only visible history. The marker is never persisted. A
matching live connection keeps the incremental request unchanged.

If an upstream stream fails before producing output, EMP discards lifecycle
noise and returns the real HTTP status at the client boundary. In particular,
an upstream 429 becomes HTTP/WebSocket status 429 rather than a synthetic
retryable stream disconnect. EMP does not disguise rate limits as quota or
invalid-prompt failures.

## Context budget

An explicit model context window is required. When an output limit is known,
EMP uses the shared Context Guard budget. When only the context window is
known, v0.7.5 reserves ten percent for output and protocol overhead. Missing
context capability fails as `context_budget_unknown`.

## User interface

- Migration import/export is a top-level action.
- Codex integration shows concise status and actions; detailed request metadata
  is available only in the Diagnostics modal.
- Model display names, context labels, and visible reasoning-summary policy are
  edited in one dedicated section.
- Provider model lists are grouped and collapsed by default.
- Modals close only through their close button, successful action, or Escape.
- Chinese/English and system/light/dark presentation are supported.

## Source references

Implementation decisions were checked against source, not README claims:

- Pi `dcd461925db2edf69a43c8135db1180d418afd54`: typed canonical messages,
  provider-owned projection, explicit compaction entries, and terminal stream
  outcomes.
- T3Code `f035a0f4cdf4abaa6704673af7b5a4a321149ba2`: ProviderAdapter isolation,
  `thread/read(includeTurns=true)`, and distinct completed/failed/interrupted
  turn states.

Neither project provides an in-place Codex cross-provider history database that
EMP should copy.

Codex source `343074d4207d572809bd8cea15f4be1d09d98e0b` was used to verify
per-request WebSocket turn metadata and retry classification. Codex treats a
streamed `response.failed` rate limit as retryable, while an HTTP/WebSocket 429
is a terminal retry-limit error; EMP therefore preserves the latter boundary.

## Verification

Keep automated coverage at the actual trust boundaries:

- failed first switch does not poison retry source or history;
- the snapshot ends before the incoming turn;
- App Server and rollout readers exclude unsuccessful turns;
- SQLite and rollout fixtures remain byte-for-byte unchanged;
- opaque remote compaction replays visible history losslessly;
- missing capability, oversized projection, missing compaction, and incomplete
  tool pairs fail closed.

Final acceptance is a real PID tutorial relay after compaction:

1. Native -> External;
2. External A -> External B;
3. External -> Native.

Each first message must continue the same files and visible requirements,
without resend or reconnect. `codex resume` and native session files must remain
unchanged by EMP.

Current implementation evidence:

- Native -> External passed on the first request against a real compacted
  Codex thread; the destination followed the new request rather than a stale
  acceptance phrase.
- External -> Native passed on the first request against the same thread.
- A real rejected external request terminated once at status 400 without a
  reconnect loop.
- External A -> External B remains a live acceptance item because the available
  second upstream rejected the request independently of history reconstruction.
