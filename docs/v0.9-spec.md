# EasyMultiProvider v0.9 Architecture Convergence

Status: implementation and real Codex acceptance complete (2026-08-27)

## Objective

v0.9 is a maintenance release. It does not add Providers, protocols, Web UI,
Search behavior, persistence, or fallback policy. It localizes the facts that
previously made Codex and Provider updates touch Router and Server at the same
time.

The request path is:

```text
HTTP / Responses WebSocket
-> CodexRequestDispatcher
-> ResolvedRoute
-> HistoryContinuityEngine when required
-> selected ProtocolAdapter
-> ContextGuard over the final destination payload
-> shared transport lifecycle
-> UpstreamFailure
-> content-free diagnostics
```

## Authoritative boundaries

| Boundary | Owns | Must not own |
| --- | --- | --- |
| `ResolvedRoute` | Requested slug, source, Provider/model snapshots, resolved upstream model, protocol, dialect, endpoint and deployment identity | Request content, mutable observations, credentials outside the selected snapshot |
| `CodexRequestDispatcher` | One request's route/history/context/replay orchestration and diagnostic callbacks | HTTP framing, Web management operations, conversation storage |
| `ProtocolAdapter` | Native Responses, portable Responses, Chat Completions, or Anthropic request projection and response normalization | Route selection, history reads, final context permission |
| `stream_adapters` | Bounded SSE parsing, terminal validation, retry-safe stream lifecycle | Provider selection or history reconstruction |
| `UpstreamFailure` | One content-free status/error/reason/phase representation shared by HTTP, SSE, and WebSocket paths | Request or response bodies, retry policy changes |
| management/integration views | Credential-free Web projections | Runtime mutation or request routing |

`ResolvedRoute.provider` and `ResolvedRoute.model` are recursively immutable.
Execution uses request-local copies. An `auto` protocol attempt creates a new
route with `with_protocol()`; it never mutates the base route.

## Preserved invariants

- Codex remains the only thread/history source.
- `previous_response_id` remains transport-only and cannot invoke HistoryReader.
- Native destinations do not read rollout and do not use EMP destination
  compaction.
- External destinations read Codex history only for a full request containing a
  native opaque compaction boundary.
- ContextGuard remains the final allow/block authority over the translated
  destination payload.
- Protocol fallback remains limited to a concrete pre-output protocol
  rejection. There is no silent Provider, account, paid-model, or history
  fallback.
- Diagnostics remain content-free.

## Clean break from old internals

The former Router route helpers, AppState Codex routing methods, server replay
scope, duplicated HTTP failure classifiers, and protocol projection branches
are removed. There are no compatibility wrappers for these private interfaces.
Tests target the new module boundaries or the real HTTP/WebSocket surface.

## Verification

Automated verification is intentionally focused on the changed boundaries:

- explicit, Subscription, single-forward-Provider, and implicit Native route
  resolution;
- immutable route snapshots and `auto` protocol attempts;
- the four protocol projections and stream terminal rules;
- replay scope isolation;
- shared HTTP/stream failure classification;
- HTTP, SSE, zstd, compact, and Responses WebSocket dispatch;
- Native/External history and ContextGuard invariants.

Real Codex acceptance proved that the first request after each model switch
succeeds without a user resend:

1. Native -> External after a Native `/compact`;
2. External A -> External B after tool activity;
3. External -> Native, followed by another Native turn;
4. image plus tool call/result across those transitions;
5. repeated Native and portable compaction across the route sequence.

`codex resume` is not a separate EMP state transition. Codex restores
`InitialHistory::Resumed` from its rollout, preserves the thread identity, and
starts with a fresh WebSocket session, so the first post-resume inference is the
same full logical request path covered above. HTTP/zstd is likewise a framing
variant: EMP decodes the body before passing it to the same
`CodexRequestDispatcher`. Resume semantics are therefore covered by the Codex
0.149 source contract, while HTTP/zstd decode and dispatch are covered by the
focused integration tests rather than duplicate manual gates.

An internal `previous_response_not_found` full-request retry is allowed. A user
resend, silent history loss, changed model route, duplicate tool call, or
repeated deterministic retry is a failure.

## Explicit non-goals

- framework migration or a rewrite of the nested HTTP handler;
- Provider pooling, credential failover, or traffic balancing;
- new protocol or model catalog entries;
- Search, Web UI, configuration, credential, or migration changes;
- persisted request/checkpoint/history state;
- a version bump, release tag, or push as part of this architecture commit.
