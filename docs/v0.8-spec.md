# EasyMultiProvider v0.8 Specification

Status: implemented; current-host v0.8.1 acceptance and independent review
follow-up complete

## Objective

v0.8 closes the remaining gap between routed models and native Codex models.
The selected model may come from the current ChatGPT login, an imported
subscription, an external API, a gateway, or a local deployment; changing that
route must not change how the user starts Codex, resumes a thread, invokes
tools, watches streaming output, or continues a compacted task.

The release has six deliverables:

1. destination-model hierarchical compaction;
2. first-send continuity for Native -> External, External -> External, and
   External -> Native;
3. stable HTTP/SSE/WebSocket termination and timeout behavior;
4. a zero-history-analysis fast path for ordinary requests;
5. Codex and Provider differences confined to adapters;
6. optional ChatGPT Subscription-backed standalone web search for external
   models.

## Ownership and non-goals

Codex remains the only owner of threads, resume data, rollout history, native
compaction, and user-visible tool history. EMP may read Codex-visible history
and derive a request-local destination view. It must not:

- write `state_*.sqlite`, rollout JSONL, or App Server thread data;
- persist prompts, summaries, tool arguments, tool results, or response text;
- create an EMP conversation database or resume graph;
- recover or fabricate hidden chain-of-thought;
- silently drop history, tools, images, constraints, or the active request;
- retry an unchanged deterministic failure;
- turn a free route, search request, or failed Provider into a paid fallback.

A bounded memory-only cache of derived checkpoint text is permitted because it
is rebuildable from Codex history, disappears on process exit, and is not a
second source of truth. Cache entries are keyed by a content-free fingerprint
of the source boundary and destination capability identity. Cache keys and
counters may be logged; checkpoint content may not.

## 1. Destination-model hierarchical compaction

### Trigger

After history reconstruction and protocol-neutral request assembly, EMP
estimates the exact destination-visible payload. If it fits the destination's
safe input budget, the request follows the normal path without summarization.
If it does not fit, the destination model compacts the older visible history.

The trigger applies to native opaque compaction, EMP portable compaction, and a
full visible request. It is based on the destination model's configured or
observed safe budget, not the source model's context window.

### Atomic history units

History is split only at complete turn boundaries. A tool call and its result,
image-bearing message, file operation, command output, and associated visible
assistant continuation are atomic. The active user request is never included
in a summary chunk and is always retained verbatim.

An individual unit that cannot fit one summary request fails closed as
`compaction_unit_too_large`. v0.8 does not clip a large tool result or image
silently.

### Map and reduce

The compactor uses the selected destination Provider and model through a
low-level non-recursive call:

- `stream = false`;
- no tools, hosted search, images generated by EMP, or previous response ID;
- no history preparation callback;
- no unchanged automatic retry;
- a bounded output limit reserved before chunk sizing;
- the same Provider credentials and protocol adapter as the final request.

Each map request asks for a structured portable checkpoint containing only
visible facts: objective, user constraints, decisions, completed work, files
and code changed, relevant tool results, current state, failures, and remaining
steps. If map summaries still exceed the reduction budget, the destination
model reduces them recursively. Every stage is independently checked against
the safe budget.

The final destination input is:

```text
portable checkpoint + newest complete retained turns + active request
```

The retained tail is selected newest-first using complete atomic units. The
final translated payload must pass Context Guard before any normal generation
request is sent. Empty, malformed, oversized, or failed summaries terminate
once with a content-free `history_compaction_failed` reason.

### Reuse

Successful checkpoint text may be reused only from the bounded process-memory
cache when source boundary, visible-prefix fingerprint, destination endpoint,
deployment, model, protocol, and safe budget all match. A process restart or
any capability/configuration change causes recomputation.

## 2. First-send cross-model continuity

The same preparation pipeline serves HTTP, SSE, and Responses WebSocket
requests. It must produce these outcomes without asking the user to resend:

| Transition | Required behavior |
| --- | --- |
| Native -> External | Read visible Codex history; replace unreadable native compaction; compact only if the destination budget requires it. |
| External -> External | Reuse a valid portable boundary when it fits; re-compact for a smaller or incompatible destination. |
| External -> Native | Project portable visible history into a native-readable request; leave native authentication, remote compaction, and WebSocket behavior intact. |

Switching between the current login and imported ChatGPT subscriptions is one
native family and keeps native compaction semantics. Failed and interrupted
destination turns do not become successful history. Request-local preparation
must preserve ordering and avoid duplicate post-compaction tails or duplicate
tool call IDs.

## 3. Streaming and timeout stability

Protocol adapters report one of four explicit phases:

- connect;
- waiting for first upstream event;
- streaming after first output;
- terminal validation.

The diagnostic journal stores only phase, duration, status, retry count,
protocol, route identity, and bounded error class. It never stores request or
response content.

Rules:

- A connect or first-event transport failure may be retried once only when no
  output has been emitted and the request is byte-for-byte replayable.
- HTTP status, explicit `response.failed`, explicit `response.incomplete`, and
  context failures are terminal and are not retried unchanged by EMP.
- Once any model-visible output or tool call is emitted, EMP never replays the
  request automatically.
- A stream ending without `response.completed`, `response.failed`, or
  `response.incomplete` is `stream_incomplete`, not success.
- A declared completed response with an unfinished tool call, invalid JSON
  arguments, or missing terminal framing fails closed.
- Upstream 504, local total deadline, connect timeout, first-event timeout, and
  idle-after-output timeout remain distinct error reasons.
- Protocol auto-detection may move to another protocol only after a concrete
  protocol-rejection status and before output; timeout is not evidence that a
  different protocol is correct.

The adapter must preserve image parts, structured tool calls/results, reasoning
summary events when supported, and the upstream's authoritative incomplete
reason. Gemini or a gateway ending early must not be rendered as a completed
Codex turn.

## 4. Performance contract

The ordinary request path must not read SQLite, rollout files, hash full
history, or run compaction when there is no unreadable/portable boundary and
the translated payload fits the known safe budget.

Performance verification records medians rather than one-off timings:

- short non-compacted requests: EMP preparation overhead target under 5 ms on
  the development host, excluding network time;
- compacted history that already has a matching memory checkpoint: no model
  compaction calls;
- new oversized history: model calls are expected, but each request stays
  within the target budget and no chunk is summarized twice in one operation;
- concurrent short requests must not serialize behind history reading or
  compaction locks for unrelated threads.

These are engineering targets, not persisted machine-specific baselines.

## 5. Adapter boundaries

v0.8 uses the following ownership map:

| Adapter/module | Owns |
| --- | --- |
| History adapters | Codex App Server, SQLite locator, Legacy/Paginated rollout differences |
| Catalog adapter | Codex catalog schema and App/TUI capability projection |
| Integration adapter | Config lease, reload/restore, Codex feature toggles owned by EMP |
| Capability adapter | advertised, official, manual, and observed model limits/capabilities |
| Protocol adapters | Responses, Chat Completions, Anthropic request/response/tool/stream projection |
| Transport adapter | HTTP/WebSocket deadlines, retry eligibility, framing, terminal state |
| Router | route selection and orchestration only |

Router must not parse Codex rollout formats, contain Provider-specific payload
rewrites, implement search command schemas, or own stream parsing details.
Version-specific changes should normally require edits and focused checks in
one adapter family.

## 6. Subscription-backed standalone web search

### Selected design

Codex `rust-v0.149.0` already contains the required client-side tool loop. With
the `standalone_web_search` feature enabled, Codex exposes `web.run`, executes
the model's call through `/v1/alpha/search` for a custom Responses base URL,
and sends the returned output back to the selected model. EMP already owns that
local endpoint and forwards it to the Codex search backend.

v0.8 completes this native path instead of embedding a second agent/tool loop
inside Router. The referenced `pi-openai-web-search` implementation is useful
evidence for endpoint, authentication, command shape, recent-input privacy, and
error handling, but EMP follows Codex's own typed implementation.

### User control and credentials

Search is off until the user explicitly enables it in Web UI. The setting
offers:

- current Codex login (default); or
- one enabled imported ChatGPT subscription account.

When enabled, EMP's integration lease owns and restores only the exact Codex
feature/config fields required for standalone search. Search requests never use
the selected external Provider's API key. They use the selected Subscription
credential in memory and target the configured Codex search endpoint.

Codex's catalog field `supports_search_tool` is intentionally independent: it
controls Codex's deferred `tool_search` capability, not standalone `web.run`.
EMP therefore does not rewrite that model capability when Subscription search
is toggled. Standalone search is exposed by Codex only when its feature is
enabled and the selected model can emit the ordinary structured tool call.

### Privacy and failure boundary

The Web UI warns that search sends the search command and Codex-selected recent
visible input to the ChatGPT/Codex search service. EMP does not persist or log
that content. Authentication failure, unsupported account, disabled search,
rate limit, malformed response, and endpoint drift are explicit bounded errors.
Search never falls back to a Provider-hosted paid web tool.

The endpoint is an internal ChatGPT/Codex behavior rather than a documented
public Subscription API. The integration is isolated behind a Search adapter
and may require a small adapter update after a Codex service change.

## Verification and release acceptance

Automated verification remains focused on real boundaries:

1. one oversized compacted history exercises map, recursive reduce, retained
   tail, tool-pair integrity, final budget, and final upstream call;
2. one transport matrix covers pre-output retry, post-output no-retry, explicit
   terminal errors, incomplete stream, and distinct timeout reasons;
3. one standalone search round trip proves an external model receives
   `web.run`, EMP uses Subscription auth rather than Provider auth, and the
   result returns to the same model;
4. one short-path benchmark proves history readers and compaction are skipped;
5. compile, focused tests, diff inspection, and credential/content scans pass.

The final user-facing relay uses one PID tutorial task after compaction:

1. Native -> External;
2. External A -> External B with a smaller context window;
3. External -> Native;
4. an external model performs one harmless standalone web search;
5. a deliberately unavailable upstream produces one attributable bounded
   failure rather than a long ambiguous reconnect loop.

Each successful transition must continue the existing files, constraints,
tool state, and current request on the first send. `codex resume`, native
compaction, native session files, WebSocket support, request compression, MCP,
and authentication remain intact.

### Release-candidate evidence

- The complete offline suite passed for the P0 change set. After the final
  isolated WebSocket window-identity correction, focused transport, history,
  destination-context, and loopback regressions passed again.
- `previous_response_id` recovery is transport-only: an unavailable chain
  emits Codex's standard `previous_response_not_found` event and never reads
  rollout history.
- Native destinations never invoke HistoryReader. Rollout is read only when a
  full request targets an external model and contains an unreadable native
  opaque compaction boundary.
- Codex 0.149 remote-compaction-v2 `replacement_history` is treated as the
  latest surviving history base, followed by the successful post-checkpoint
  tail; unresolved opaque replacement state fails closed.
- Context Guard makes the final allow/block decision over the concrete
  destination payload. A destination compaction is projected and checked again
  before sending.
- Current-host acceptance covered first-send Native -> External, External ->
  External, and External -> Native continuity after compaction, plus tool
  results, image input, standalone web search, compressed large requests,
  subsequent WebSocket turns, and native `resume`.

Cross-platform packaging and additional upstream sampling are separate
hardening work, not claims of this acceptance record.

### v0.8.1 compatibility closure

- Codex 0.150 named standalone function outputs remain native Responses items
  when supported and become explicit visible context for Chat Completions and
  Anthropic without fabricated call IDs.
- Native ownership uses one shared dialect classification. Forwarded Native
  routes do not read rollout history or invoke EMP destination compaction.
- Provider replay identity includes the resolved upstream model; SSE event and
  pre-output retry buffers have aggregate byte limits.
- A first structured context failure remains immediately fail-closed but stops
  controlling after 24 hours or after a later success reaches the same bound.
- Multi-file Provider-key saves and `.emp` account imports restore previous
  encrypted credentials when their configuration commit fails.
- Current-host Codex 0.150.1 acceptance covered Native opaque compact to
  External, External portable compact to External, External to Native, image,
  tools, and resume.
